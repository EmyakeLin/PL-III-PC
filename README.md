# 光点计划 III

两名玩家共用一个终端，各选 1～3 名角色，把他们的技能洗成自己的牌堆。双方先扣置常规技能，再声明并结算开牌前交锋，最后统一开牌、结算常规交锋。消灭对方全部角色的一方获胜。

完整的对局流程、词条裁决与角色技能费用见[《光点计划 III》正式规则书](./docs/正式规则书.md)。此前的版本交付与阶段决策见 [v0.0.1m10 阶段记录](./docs/releases/v0.0.1m10.md)。

## 开始对局

### 浏览器中的极简对战

在项目目录运行以下命令，打开 [本机战场](http://127.0.0.1:8765/)。这张战桌供两名玩家在同一台设备上各操控一名角色。初始配对为安诺琳与莱克，使用页面的“新对局”可以从已载入的角色中重新选择双方。

```powershell
python -m battle_ui
```

轮到自己时，选择手牌并确认扣置。交接时先把屏幕交给另一位玩家，再由接手者查看手牌。开牌前进攻与迎击都围绕公开的交锋编号操作。玩家可以先看对方的反应，继续出牌、暂缓回应，或从数个待迎击的编号中选一个处理。双方结束进攻且每场都已就绪时，逐场结算。刷新页面会回到当前进度。可用 `--seed 37` 固定随机种子，或用 `--port 8766` 更换端口。

### 命令行对局

在项目目录运行以下命令。游戏使用 Python 标准库，已在 Python 3.12 和 3.14 上验证。

```powershell
python main.py
```

1. 选人时输入编号加入队伍，输入 `?编号` 查看角色的全部技能，选够后按回车。想先熟悉操作，可以双方各选一名。
2. 速度较高的一方先扣一张。接下来每次持有置卡权可扣至多两张。终端提示换人时，把终端交给下一位玩家，再按回车看牌。
3. 输入手牌编号后，`y` 扣置，`pass` 扣置并交权，`end` 扣置并结束本回合置卡。也可以在选择手牌时按回车，两次确认后直接结束置卡。费用到技能使用时才支付。
4. 结束常规置卡后，两人共看公开桌面的交锋编号。想行动的人选择自己名下的「主动出牌」或「回应开牌前交锋」并接手终端。选牌或瞄准时按回车可暂缓并交回屏幕，原来的交锋仍待迎击。要放行，在对应编号的选牌菜单明确选择「放行」。结束自己的进攻时，在公开桌面选择「结束主动进攻」。
5. 开牌前双方的主动进攻均已结束、每个编号都就绪后，按编号结算，再统一开牌。常规单方面攻击需要选敌时，按回车采用默认目标。

用 `python main.py --seed 37` 可以在做出相同选择时复现同一局。加上 `--step` 可逐节点推进，查看两条阵营管线的等待、拼点和命中。用 `--packs 目录` 可载入指定目录中的 JSON 卡包。

## 卡包与规则

### 共享效果包

对局启动时会载入以下三个包。即使用 `--packs` 只选一个角色包，角色也能使用这些效果。自定义目录下的 `effects/*.json` 可以提供额外的共享定义。

| 效果包 | 定义 |
|---|---|
| [基础状态效果包](./_packs/effects/base_statuses.json) | 强壮、虚弱、迅捷、束缚、骰子等级提升、骰子等级降低、限制、凝聚 |
| [基础体系状态效果包](./_packs/effects/system_statuses.json) | 烧伤、裂血、呼吸、失衡，以及由失衡产生的致命失衡 |
| [基础能力效果包](./_packs/effects/base_abilities.json) | 置卡机会、换卡机会 |

状态效果用 `STATUS`、`SPEND_STATUS`、`STATUS_COUNT` 获得、消耗和读取层数。能力效果用 `ABILITY_EFFECT`、`SPEND_ABILITY_EFFECT`、`ABILITY_COUNT` 管理可用次数。角色包可在 `ability_rules` 中声明一项能力的操作和持续时间。例如，空白的「智脑」抽牌一次，同时花 1 次抽卡资格和 1 层能源，分别结算能力支付和状态消耗。[空白卡包](./_packs/void_boss.json)

骰面写 `"引燃"` 即可立即结算目标当前的烧伤。技能、状态等来源可用 `{"op":"ignite"}`；需要翻倍本次烧伤伤害时，用 `{"op":"ignite","multiplier":2}`。每次引燃按当时的层数结算，伤害归触发它的实体。[烧伤与引燃定义](./_packs/effects/system_statuses.json)

### PlanB 精英 · 赫克

赫克以 12 生命、3 个基础常规交锋和 5 张常规技能入场。回合开始时有至少 12 能源，就在该回合全开，首次全开将两张决战技直接加入手牌。「装填」随即切换为强化远程的「开火」。能源影响下一回合能否全开，弹药在每颗有要求的骰子使用时支付。运行 `python -m tests.test_heck_match --replay 1` 可复盘赫克从零能源入场、第三回合全开对战安诺琳的整局。[赫克卡包](./_packs/plan_b_heck.json)

### 新星组织首领 · 林秋

林秋以隧道开启强化技能，凭羽流追加命中，以星结标定目标。命令行和浏览器均可选用他的七张技能。运行 `python -m tests.test_lin_qiu --replay 50` 可重放他与安诺琳、莱克的完整对局。[角色卡包](./_packs/xinxing_lin_qiu.json) · [正式规则书](./docs/正式规则书.md#appendix)

### 光点形态群完整度与两名新首领

所有角色以满完整度入场。光点伤害直接扣完整度，归零触发崩塌并造成真实伤害。每崩塌一次，完整度上限减少 4。回复前普通生命已达到当前完整度上限且实际回到血时，角色立即阵亡。卡包分别通过 `DAMAGE`、`LIGHTCORE_DAMAGE` 和 `REAL_DAMAGE` 结算直伤、光点伤害与真实伤害。后两种有各自的事件，监听 `AFTER DAMAGE` 的词条只收到直伤。[正式规则书 · 第六章](./docs/正式规则书.md#chapter-6)

骰面可直接写 `"7光点伤害"`。另一个命中词条若执行 `["$target", 4, "LIGHTCORE_DAMAGE"]`，就对同一目标追加独立的 4 点光点伤害。卡包监听 `AFTER LIGHTCORE_DAMAGE` 时，用 `lightcore_collapsed` 判断本段是否引发崩塌，用 `$lightcore_lost` 读取本段实际扣掉的完整度。

「铸钟人」阙鸣用近战打光点，蓄积钟振后可在开牌前掷出强化远程「百步飞椎」，改攻普通生命。「拆船师」沈砾给敌人画上粉线，以穿甲与光点分段追击。两人各有七张技能。运行 `python replay_lightcore.py all --seed 40 --log` 可重放他们挑战安诺琳＋莱克、挑战东部四科三人以及彼此交手的五场比赛。[光点首领战报](./docs/光点首领战报.md)

### 空白镜像对局

两名玩家可各选一名「空白」，使用各自的七张技能。置卡时可用洞察翻正敌方一张扣牌，开牌前可用「智脑」抽牌或弃牌。「看破」取得的牌按实体区分，用完回到原印刷角色的牌堆。运行 `python -m tests.test_blank_mirror --replay` 可以查看固定种子的完整镜像战报。

「看破」在交锋开始前命中时，用 `TAKE_HAND_CARD` 取得对方的实体牌。卡包读取牌费、手牌和可追加的交锋，按牌费支付能源并用 `SKILL_USE` 记录本次技能费已代付。`CHOOSE_SLOT` 让玩家选择交锋，选定后的词条用 `INSERT_AT` 指定队尾，再用 `INSERT_SKILL` 追加该牌。其他词条可复用选交锋操作，并自行决定选定后的效果。没有合适交锋或能源不足时，「看破」把牌留在手中。[「看破」词条](./_packs/void_boss.json)

### 特殊置卡、换卡与闻笙

「置卡机会」让持有者从手里向第一个友方空常规交锋补一张技能。使用机会或牌面许可补牌时，都要有剩余常规交锋额度，成功补牌占用 1 个额度。「换卡机会」在自己一张技能即将使用时生效。牌上明写可在任意时刻打出或替换时，还可以在已经使用技能、用骰或命中后行动。换下的牌回手，已付费用保留。换入牌重新付费，从第一骰开始。若已配对的骰子在判胜负前消失，本轮只给对面的骰子记胜。[正式规则书](./docs/正式规则书.md)

余烬剧团的精英「替演领班」闻笙有 12 生命、2 个基础常规交锋。「候场」每回合额外抽 1 张并提供 1 次换卡机会。「点名上场」提供置卡机会，「飞场」可以即时进攻或补位，「救场」可以随时换下自己的在场技能。运行 `python -m tests.test_special_elite --replay` 可复现闻笙对安诺琳的完整战报。[闻笙卡包](./_packs/yujin_theatre.json)

卡包用 `["$self", "置卡机会", 1, "ABILITY_EFFECT"]` 授予一次置卡机会。牌面自带的 `anytime_play` 列出允许的 `attack`（主动进攻）、`place`（置入空交锋）或 `custom`（按卡面处理）。`custom` 的牌先从手牌移入延迟弃牌区，再触发 `on_anytime_play`，由牌上的词条规定费用、效果与去向。`anytime_replace: true` 默认允许替换同角色的技能，附上 `replace_targets` 可以按技能 ID 指定允许替换的友方技能。调换走 `REPLACE_SKILL`，成功后产生 `on_skill_replaced`。

### 开牌前交锋

先手方先取得进攻权。每主动打出一张允许在开牌前打出的手牌，就新开一个编号并指定一名敌方角色或一个已置的常规交锋。进攻方可以等对手表态，也可以在先前的牌仍待迎击时继续加牌。防守方可观察整列声明，再从待迎击的编号中任选一个回应。除非进攻牌另有说明，任意手牌均可被动打出迎击。成功迎击使该场转火到迎击牌，明确放行则使该场以空位就绪。玩家考虑多久由自己决定。已经打出的牌锁定，已就绪的编号无法通过普通置卡补牌。

每方只有一次主动进攻窗口。甲对乙打出①②后可以结束进攻，将进攻权交给乙。此时甲的①②都可继续待迎击。乙可以先对甲发起③，再回来迎击②，留①继续考虑。双方都结束主动进攻后，仍可回应对方向自己打出的待迎击牌。等所有编号都已就绪，才从①起依次结算，费用在技能使用时支付。

即便乙用最后一张手牌迎击了②，①仍然待迎击。乙可以明确放行①，也可以等词条补牌后再迎击。浏览器在每个编号下显示自声明起经过的时间，到该场就绪时停表。时间只供双方观察，换手和刷新都不会关闭回应机会。

某场若仍指定常规交锋，到该场开始结算时才将对手在对应位置的牌牵制过来并公开。成功迎击保留原扣牌。若较早的进攻已牵走那张牌，后来的进攻改为单方面攻击原持牌角色。实现中，同一侧有多张扣牌时每次牵走下一张可用牌。从未有牌的位置，或已经阵亡的原持牌角色，无法提供目标。全部开牌前交锋结束后，再统一公开剩余常规牌。

### 远程等级

远程等级分普通 1、强化 2 和极限 3。对阵双方先按远程等级相抵，劣势方的无视远程再抵消剩余等级。例如极限远程对普通远程时有二级优势；若普通远程还无视一级远程，便只剩一级优势。远程和开牌前打出是两个独立属性，在开牌前与常规交锋中使用同样的远程规则。

| 抵消后的优势 | 劣势技能如何结算 |
|---|---|
| 1 | 无法命中，也不能对优势技能的使用者施加效果。仍然拼点，自身的词条能按其时点生效。 |
| 2 | 继承一级。劣势骰若点数较高，双方照常记录胜负，但整个胜方的拼赢分支跳过。劣势技能进行单方面攻击的骰子变为空白。 |
| 3 | 继承二级。劣势技能成为空白技能，技能词条全部失效，所有骰子变为空白骰。双方仍支付技能费用，空白骰仍可参与拼点。 |

例如二级劣势骰以 10 对 4，原始结果仍为劣势方胜、优势方负。劣势方不触发拼赢词条和命中，优势方仍能触发拼输词条。安诺琳如果用闪避骰取得这个胜场，也不满足「翠流漂泊」的未胜条件。

卡包技能使用 `pre_reveal` 声明开牌前主动出牌资格。未写 `interceptable` 时，开牌前序列内的主动进攻默认可迎击，场内独立发起的即时进攻默认不可拦截。显式填写 `true` 或 `false` 时以卡面为准。`range_level` 和 `ignore_range` 为 0～3 的整数。词条还可以在 `RESOLVE_RANGE_DEFICIT` 时通过 `VALUE_CEILING` 等现有指令调整实际生效的远程劣势。

从手牌主动打出或被动迎击会发出 `on_pre_reveal_play`。词条可以通过 `$play_mode` 区分 `active`（主动）、`passive`（迎击）与 `pulled`（结算时被牵制）。牵制不会再触发一次从手牌打出的事件。

### 白崖测绘员 · 岑遥

雾港测绘局精英，9 生命，五张牌。被动「潮汐手簿」每回合额外抽一张，若校准为零则获得一层，上限三层。三张远程牌均可在开牌前主动打出。1 费「试水标」首骰命中积攒校准；2 费「双标成线」付足一层校准使本技能最终点数 +2；4 费「地平线回声」付足两层校准使每颗骰的伤害 +1。两张近战牌分别是无视一级远程的 1 费「折尺架势」，以及使用时获得两层校准的 2 费「收线换尺」。[岑遥卡包](./_packs/wugang_survey.json)

### 其他卡包

原示例卡包包含铁壁先锋和绯红决斗者。本次补入了部分原来空缺的伤害数值，并为「决意贯穿」加入拼点胜利后从战斗外追加「尖刺必杀」的效果。独立的演练卡包提供斥候、医护、队长和重装机，使双方可以各选三人。这些新增数值和角色是可玩的示例内容。

[WAA东部四科](./_packs/waa_east_four.json)提供三名常人。莱克（6 生命）擅长第一交锋；格罗琳娜（6 生命）依靠队伍速度和上一交锋的结果增强技能；厄尔克斯（9 生命）在充能与最多 5 层纯能之间调度资源，三张技能依次为 1、2、5 费。选人时输入 `?编号` 可以看阵营被动、角色被动和每张牌的骰子词条。

己方手牌从不足 3 张升至至少 3 张时，「WAA东部四科」使每名存活队友获得 1 层充能。三名代理人同队，首回合从空手抽到 3 张时也只触发一次。手牌跌回 2 张后再抽到 3 张，可以再次触发。

每名存活角色分别投速度骰，自己的迅捷增加速度，束缚减少速度。阵营去掉一名最低速角色，再取剩余角色速度的平均值；单人直接用自己的速度。强壮和虚弱作用于所有非空白骰的最终点数，招架和闪避也生效。检视骰子的基础值或掷出的原始点数时，看到的是加减威力前的数值。

卡包中的 `program` 保存按顺序求值的逆波兰指令。`$self`、`$card` 和 `$die` 引用当前角色、技能和骰子。例如「猛烈斩杀」用 `SPEND_STATUS` 消耗全部充能，再按实际扣除的层数计算技能加成。「借机」用 `NEXT_TURN_COST` 预约下回合通用费。「武器增压迸发」在使用时先按当前充能计算最终点数加成，再消耗全部充能。消耗前不足 8 层时，厄尔克斯在第一颗骰子前获得能源封印。第二颗突刺骰按本技能已实际消耗的充能提升骰子等级。尾骰触发 `REPEAT_DIE` 时，把一次新的用骰排进当前交锋，双方继续按骰位配对。

充能、纯能和涡流按实际持有量扣除。只剩 1 层却要消耗 2 层时，这 1 层也会扣掉。「消耗 2 层并……」用 `SPEND_STATUS` 取得实扣数，后半句照常执行。「消耗 2 层以……」用 `SPEND_STATUS_IN_FULL` 取得足额与否，再用 `WHEN` 决定是否执行后半句。这两种卡包写法都执行一次相同的 `SPEND_STATUS` OpCode。过载的额外消耗计入应付数，按消耗量触发的被动和骰子升级读取实扣数。

### 飘流翠风 · 安诺琳

安诺琳是 PlanB 的精英，9 生命，初始可参加 3 次交锋。五张技能依次是 1 费「漂泊剑法」、2 费「剑携涡流」、2 费「流风习习」、3 费「翠流迸发」和 5 费「飘流翠风」。选人时输入问号和安诺琳当前的编号，可以逐骰查看技能。[安诺琳卡包](./_packs/wind_plan_b.json)

首回合获得 4 涡流。拼点时先结算骰级、掷骰和最终点数，再从最终点数得出拼点点数。例如持有 8 层涡流时，最终点数 4 的骰子以 8 点拼点，词条读取最终点数仍得到 4。涡流贡献的保底最高为 10，原本掷出的高点数照常参与拼点。卡包通过 `VALUE_FLOOR` 和 `VALUE_CEILING` 给当前结算值设置边界，同一套指令也能把有效骰级固定在印刷等级。

回合开始时，「A级条目」先额外抽 1 张牌并回复 2 生命，再由「PlanB 组织」检查安诺琳自己的五张技能是否全在己方手中。额外抽牌恰好补齐第五张时，也能当回合多获得 1 次个人交锋，己方通用费增加 1 点，可以超过常规回补值。

「翠流漂泊」在安诺琳的闪避骰拼点失败、打平或跳过拼点时发动，每次回复 1 生命并获得 1 涡流。三种结果共用每回合 2 次的额度。

「漂泊剑法」仅在首骰命中时获得回手效果，整张牌使用完毕后才回到手中。尾骰单方面攻击下一交锋的目标，下一交锋没有目标时跳过该骰。「翠流迸发」首骰命中会直接失去 4 生命，护盾照常保留。安诺琳若因此阵亡，本技能余下骰子随她退场。

回合时刻表、骰子、费用、状态和护盾的原始说明见[游戏规则](<AI chat/chat (1).md#L227>)。交锋由一条主管线和两条阵营管线驱动，原型中的等待和展开规则见[动态管线设计](<AI chat/SidePipeline采用动态展开的加载方式。.txt>)。

## 前端读取对局

用 `Displayer` 包装正在运行的 `Game`。每个视角分别创建一个实例。选人完成后可以读取印刷规则，在游戏循环每次推进并返回后读取一帧。两个方法都返回独立的 Python 字典，可直接序列化为 JSON。[只读适配器](./displayer.py)

```python
import json
from displayer import Displayer

public = Displayer(game)
player_view = Displayer(game, viewer_side=game.players[0].side)
rules = public.catalog()
frame = player_view.snapshot()
payload = json.dumps(frame, ensure_ascii=False)
```

| 快照字段 | 用途 |
|---|---|
| `turn`, `phase`, `node` | 当前回合、界面阶段和主管线节点。开局前回合为 0。置卡和统一开牌之间可出现 `pre_reveal`，对局结束为 `finished`。 |
| `players` | 双方队伍、速度、通用费、角色生命、完整度、三种护盾、状态和个人费。每名角色的 `lightcore_hp` 与 `max_lightcore_hp` 公开当前完整度与当前上限。四个牌区都有张数，玩家还能查看自己的手牌、待回收牌和战斗外牌。双方抽牌堆都只显示张数。 |
| `duels` | 按交锋顺序列出两侧的牌。自己的扣牌可见，其他视角在开牌前只收到 `{"hidden": true}`。开牌前，其他视角的逐角色已用交锋数也隐藏。 |
| `pre_reveal` | 开牌前声明阶段、当前行动方、进攻方和公开交锋序列。每场包含编号、就绪状态、目标及实际牵走的牌。该场结算前不会公开目标常规槽的牌面。 |
| `combat` | 活跃交锋及双方管线的节点、等待位置、出牌与当前骰。骰子的 `base_value`、`rolled_value`、`final_score`、`clash_score` 分别为基础值、变动点数、最终点数、拼点点数。尚未产生的结果为 `null`。交锋号、实际用骰序号 `die_number` 和印刷骰位 `position` 都从 1 起算。 |
| `is_over`, `winner_side` | 终局时读取胜方。终局且胜方为空表示平局。 |

`catalog()` 提供已选角色的公开被动、印刷技能、骰面和状态词条，可供详情面板复用。它与当前牌区无关。同一线程在两次推进之间读取快照，能得到一致的一帧。要回放逐步动画，由驱动对局的一侧按顺序保存这些帧。当前命令行在一次置卡步骤内部完成输入，快照反映已写入对局的状态。

`combat.kind` 区分 `pre_reveal` 和 `regular`，两者各自从交锋 1 起算。每一侧的 `range_deficit` 为抵消后剩余的远程劣势；骰子的 `result` 保留点数比较结果，`win_branch_skipped` 单独表示因远程压制跳过拼赢分支。
