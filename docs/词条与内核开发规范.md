# 词条与内核开发规范

## 从卡面写出一条 entry

先写清楚谁在什么时点，依据哪件已发生的事，对哪个对象做什么。有次数或费用时，再写清什么时候占用次数、什么时候扣费。以下是一条教学用的角色被动，可以直接放进被动技能的 `entries` 数组。

> 自己的骰子命中时，本轮前两次各抽 1 张牌。

<!-- example: round-draw -->
```json
{
  "description": "自己的骰子命中时，本轮前两次各抽1张牌。",
  "trigger": "on_dice_hit",
  "subject": "source",
  "operation": {
    "op": "program",
    "code": [
      "$self", "回响", "ROUND_TRIGGER_COUNT", 2, "LT",
      ["$self", "回响", "RECORD_ROUND_TRIGGER", "DRAW 1"], "WHEN"
    ]
  }
}
```

`ROUND_TRIGGER_COUNT` 读取这名角色在本轮以「回响」登记的次数。`2 LT` 比较卡面给的上限。条件成立后先登记这次命中，再抽牌。因此，即使牌堆已空，这次命中仍占一个名额。把“前两次”改为“前三次”只需改比较数，把“各抽 1 张”改为“各抽 2 张”只需改 `DRAW` 的参数。「轮」是双方当前骰子推进的一轮，区别于包含多场交锋的「回合」。[正式规则书 §1.5、§8.3](./正式规则书.md)

旧写法 `once_per_round(key)` 的决定性问题是把**查询与常数 1 绑死**。即使删掉登记动作、改为只返回布尔值，作者依然读不到当前次数，也不能用同一个查询表达“两次”。反过来，`DRAW 1` 里的 1 明明白白来自卡面，设计者可以换它。判断同一段代码是否合格，要对照它承诺的语义，追到实际读写的对象和时点。

## 新角色与新指令怎样落地

| 改动的位置 | 该位置负责的决定 | 在本项目中怎样写 |
| --- | --- | --- |
| 角色或状态的 entry | 卡面独有的数量、对象、顺序、费用、作用范围与寿命 | 作者决定先筛谁、是否取首张、按整次命中还是当前伤害段加成。需要玩家选人时显式调用 `SELECT_SKILL_TARGET`，读取已有目标用 `$event.target`。 |
| builtin | 让一组含义明确的指令可以简写 | 用 `@builtins.define(...)` 注册展开函数，由实参产生普通程序指令。`DRAW 1` 展开后走同一个 `DRAW`。`CAP_STATUS` 由作者给出持有者、状态名和上限。新的通用体系可以像算术和集合指令一样单列模块，并接入 builtin 注册入口。 |
| OpCode、模型与管线 | 提供可独立说明的动作、可观察的事实，以及正式规则定义的共同结算 | 例如 `DISCARD` 把指定实体手牌移入延迟弃牌区。林秋要弃目标手牌的第一张，由他的 entry 先取 `FIRST`。新效果先用已有能力拼出，在确实缺少的那个动作上补后端，并写明输入、输出及副作用。 |
| 顶层桥接器 | 把后端提供的事实与待选项交给界面，再把玩家选择送回顶层 | 本地命令行由 `main.py` 组装 `TerminalBridge`。模型、词条、OpCode 与管线通过状态、事件或待处理选择表达进展。终端的 `input`、`print` 和展示格式由桥接一端处理。 |

用一条反事实来审查抽象。假设下一张牌需要相同的查牌动作，但要选第二张、允许被摧毁的牌，或者只想预览。检查通用操作能否忠实返回它承诺的数据，让新牌独立决定后续动作。游戏规则明确规定的敌我关系、阵亡和费用结算，照其本义实现即可。词条长度、分支数和内核行数都不用于裁决语义。[作者指令注册](../entry/commands.py) · [编译器](../entry/compiler.py) · [操作数与执行器](../models/opcodes.py) · [顶层桥接器](../terminal_bridge.py)

## 这次重构确立的执行路径

| 卡面语义 | 现在沿哪条路径执行 | 最能区分对错的情况 |
| --- | --- | --- |
| “拼赢”“实际重复”“本骰造成” | 赫克读取本次用牌实例中各骰的 `clash_result`，在重复骰实际使用时计数。额外命中携带自己的来源。 | 拼赢效果受压制仍有胜场。已经请求但没有使用的重复骰不计。另一个效果也安排了仅伤害命中时，只修改本条排入的那一次。 |
| “使用时的目标”“群伤主目标优先” | 安诺琳在使用时保存涡流目标，技能结束向同一对象扣层。群伤在成功命中后显式安排主目标顺序。 | 中途换目标、旧目标已无涡流、命中返回失败、主目标本来排在最后。 |
| “实付”“本次引燃移除”“获得量” | 用 `SPEND_STATUS` 的本笔回执取实付数。引燃奖励对照实际签发扣层操作的 entry。监听 `BEFORE STATUS` 时，用 `$pending.amount` 比较前面监听者调整后尚待执行的数值。 | 同一张牌还有一笔支出，旁支监听也扣同一状态，或本笔正增量已被前一个监听减到零。 |
| “本段伤害”“本次命中” | 作者显式把 `$event.modifiers` 或 `$event.hit_modifiers` 交给 `ADD_DAMAGE_MODIFIER`。关键词伤害归属由 `credit` 指定，阶段数值规则由 `adjustments` 声明。 | 同一次命中含多段伤害。嵌套发动时，引发本次效果的骰与外层事件的骰不同。 |
| “下回合”“目标下一次实际用骰”“本回合可迎击” | `schedule` 指定事件、来源、对象、起止回合、次数、存活条件及执行体。`capture` 保存预约时的值。迎击词条指定骰样本、期限及扣次点。 | 林秋「铭刻逆流」施加后来源阵亡，存活目标的下一颗实际用骰仍减 4。已撤回的骰保留预约。预览迎击保留次数，实际支付按当时的费用修正结算。 |
| “当前凝聚”“使用时的凝聚”“本回合符合条件的名单” | 赫克的射程读当前层数，赫里斯按牌面时点保存用牌快照。星结在回合收尾冻结名单、发布事件，再处理清零与封顶。 | 快照值是 0 后又获得凝聚。事件监听期间，原名单外的角色达到星结门槛。 |

林秋「空断」的两项裁定已写进骰面。隧道开启时，只有 1 层也会扣掉这一层并激活。该骰每次命中都使目标减少 2 星结，包括未激活时。另两项沿用的顺序也可直接在各自的 entry 里查到：「铭刻逆流」弃首张手牌，「漂泊剑法」在下一交锋取首名合法敌手。[林秋](../_packs/xinxing_lin_qiu.json) · [安诺琳](../_packs/wind_plan_b.json) · [赫克](../_packs/plan_b_heck.json) · [赫里斯](../_packs/plan_b_heris.json) · [李凌](../_packs/plan_b_li_ling.json)

已迁移并核对的范围是 PlanB 与新星组织的五份角色文件及其中的状态定义。此次审计的 108 条合格项都按原文和触发器对回，其中 49 条的完整 JSON 值相同。旧字段别名与旧操作翻译模块已删除。作者应直接使用显式事件字段、`when` 比较列表和当前操作。新增语法时，同步迁移获准修改的调用方。涉及未核对的包，记录实际覆盖范围。

## 用执行路径验收改动

1. 在改动说明里写出卡面原句或规则条款，指出哪一个数值、对象、时点或归属由它决定。遇到会改变玩法的两种文义，分别给出一个具体结果，交由设计者裁定。
2. 找一对旧实现容易混淆的局面，例如“目标为空”和“目标存在但有 0 层”，或“曾经请求重复”和“已实际用过重复骰”。先让其中一例在错误实现上暴露差异。
3. 经真实编译器和执行器改变这个维度。数量取 0、1、阈值两侧和大数，枚举遍历适用值。只对合法输入要求成功，同时核对非法输入的报错。断言读取的是哪个对象、调用顺序、实际回执与写入次数。对条件为假的分支也检查是否发生了选人、支付或记账。
4. 改 builtin 时核对展开后的指令和实参，再让简写与展开式走同一套执行器。修改预约、选择或伤害时，至少覆盖一次会使外层来源、目标或数额发生变化的情况。测试聚焦被改动的解析或执行单元。

在仓库根目录可单独运行这组路径测试。

```powershell
python -m unittest tests.test_entry_execution_paths tests.test_die_response_semantics tests.test_range_amount_semantics tests.test_scheduled_effect_semantics
```
