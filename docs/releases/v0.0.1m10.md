# v0.0.1m10 · 常规交锋、角色卡包与本机战场

2026-11-20。基线为 `v0.0.1m09`（`74d57c2`）。本阶段打通了从选人、扣置技能到阵亡判负的完整对局。命令行支持每方 1～3 名角色，浏览器支持同机双人 1 对 1，两者共用动态管线和 10 名可选角色。[运行说明](../../README.md)

## 引擎与卡包的分工

主管线负责回合、开牌和交锋顺序，两条阵营管线逐个展开技能、骰子、拼点和命中。遇到双方骰数不同、同槽接续技能、重复用骰或角色中途阵亡时，各方按实际剩余行动继续。技能在使用时支付费用，先扣个人费，再扣通用费。[动态交锋](../../pipeline/pipeline.py) · [分段时序](../../pipeline/combat_steps.py)

卡包通过事件、词条和逆波兰 `program` 表达角色规则。引擎在手牌增减时广播通用事件，由卡包判断是否跨过触发阈值。过载的“禁止获得充能”和“额外消耗充能”分别声明。能源封印锁定的资源和解除条件也由卡包决定。跨回合状态、按实扣层数结算、原卡回手、骰子改换目标和群体效果均可由其他角色复用。[指令执行](../../models/opcodes.py) · [卡包程序](../../entry/program.py)

## 已定规则与回归依据

| 主题 | m10 采用的结算口径 |
|---|---|
| 点数与骰级 | 先结算有效骰级和掷骰，再用基础值、变动点数及修正算出最终点数，最后得出用于比较的拼点点数。强壮与虚弱作用于所有非空白骰的最终点数。涡流仅为拼点点数设置下限，最多计入 10 层。通用边界指令为 `VALUE_FLOOR` 和 `VALUE_CEILING`。 |
| 资源与生命 | 充能、纯能、涡流遇到不足额消耗时扣尽余量。“并”的后半句继续结算，“以”的后半句须足额才生效。失去生命直接扣到零，可导致阵亡，即使有护盾也一样。阵亡会取消该角色的后续行动。 |
| 费用与速度 | `TURN_COST_ADD` 修改本回合可用费用，可超过回补值。迅捷与束缚修改所附角色的速度。存活角色多于一名时，阵营去掉一名最低速角色再取平均，单人直接使用自己的速度。 |
| WAA 东部四科 | 莱克、格罗琳娜和厄尔克斯已接入。己方手牌从不足 3 张跨入至少 3 张时，阵营统一触发一次充能。重复的“直属·α”已移除。厄尔克斯的技能依次为 1、2、5 费，“武器增压迸发”在使用时消耗充能。 |
| 飘流翠风·安诺琳 | 9 生命、5 张技能、初始 3 次交锋。“A级条目”额外抽牌后，“PlanB 组织”才检查自己的五张技能是否集满。“漂泊剑法”首骰命中后，原卡在技能使用结束时回手。尾骰在下一交锋没有目标时跳过。闪避输、平、跳过三种结果共享“翠流漂泊”每回合两次的额度。 |

例如，“翠流迸发”首骰命中后，剩 3 生命的安诺琳会因失去 4 生命而阵亡，余骰随她退场。她若存活，+15 加到实际发动的下一颗骰子，包括重复使用的首骰。这个用例同时检验了生命流失、中途阵亡和动态骰序。[东部四科卡包](../../_packs/waa_east_four.json) · [安诺琳卡包](../../_packs/wind_plan_b.json) · [安诺琳回归](../../tests/test_annolin.py)

## 展示与验证

`Displayer.snapshot()` 输出与引擎对象分离的局面，`catalog()` 输出公开印刷规则。观众与玩家各有独立视角，扣牌在统一开牌前对其他人隐藏，双方抽牌堆都只显示张数。浏览器战场用这些数据呈现选牌、交接、开牌和逐次结算。重复读取同一帧不会消耗随机数或再次触发词条。[Displayer](../../displayer.py) · [浏览器对战适配器](../../battle_ui/match.py)

封版时运行 `python -m unittest discover`，133 项全部通过。另用 `python -m DynamicPipelines.test_runner` 单独复核“三骰对同槽两张双骰，再进入下一交锋”。运行 `git show "v0.0.1m10:战斗日志/WAA东部四科_vs_混编队_20261120_1120.log"` 可查阅这场 3 对 3 对局的具体行动和终局生命。[测试目录](../../tests/)
